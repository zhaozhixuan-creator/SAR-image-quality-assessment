# 自研模块 · 元数据规则引擎

> 对应维度 7（完整性与元数据）的落地实现。用 stac-check 的规则引擎结构 + CEOS-ARD 条款清单，逐条输出 Threshold / Goal 自评，而非笼统给一个合规结论。

## 1. 需求背景

CEOS-ARD / CARD4L 是元数据与处理链规范，不是精度门槛规范。它要求每条条款附**自评栏**（Achieved level: Threshold / Goal + 说明 / 理由）。因此元数据质检的正确形态是一个**规则引擎**：逐条校验字段、逐条输出自评，而不是布尔"合规 / 不合规"。

## 2. 引擎架构

参考 stac-utils/stac-check 的规则结构（JSON Schema 校验 + 最佳实践 lint），可作自研规则引擎范本。

```
输入：产品元数据（STAC / SAFE XML / 自定义 JSON）
  │
  ├── 规则集 A：字段存在性校验（Threshold 级）
  ├── 规则集 B：字段值域 / 格式校验
  ├── 规则集 C：条款自评（Threshold / Goal）
  └── 规则集 D：跨字段一致性校验（版本台账、定标可追溯）
  │
输出：逐条规则结果（pass / fail / warning + 理由）+ 自评表
```

## 3. 规则设计

```python
# 规则统一接口
class Rule:
    def __init__(self, name, clause_ref, level):
        self.name = name              # 规则名
        self.clause_ref = clause_ref  # 对应 CEOS-ARD 条款号
        self.level = level            # "Threshold" | "Goal"

    def check(self, meta) -> Result:
        """返回 Result(pass, level_achieved, reason)"""

# 示例：噪声相关条款（CEOS-ARD 要求提供 NEσ⁰/NEβ⁰/NEγ⁰）
class NoiseMetadataRule(Rule):
    def check(self, meta):
        has_noise = any(k in meta for k in ("noise_range", "noise_azimuth"))
        return Result(
            pass=has_noise,
            level_achieved="Threshold" if has_noise else "None",
            reason="缺少噪声矢量" if not has_noise else "",
        )

# 示例：相干性估计参数（CEOS-ARD 要求提供统计阈值、估计窗口大小）
class CoherenceParamRule(Rule):
    def check(self, meta):
        has_win = "coherence_kernel" in meta
        return Result(
            pass=has_win,
            level_achieved="Threshold" if has_win else "None",
            reason="未报告相干性估计窗口" if not has_win else "",
        )
```

## 4. 核心校验维度

| 维度 | 规则内容 | 依据 |
|---|---|---|
| 通用元数据 | 产品族、采集参数、坐标系、参考框架 | CEOS-ARD 章节 1 |
| 逐像素元数据 | 局部入射角、散射面积、噪声功率、数据掩膜 | CEOS-ARD 章节 2 |
| 辐射校正 | NEσ⁰/NEβ⁰/NEγ⁰、噪声减除时实际使用的噪声估计 | CEOS-ARD 章节 3 |
| 几何校正 | 精度数值、所用方法名与引用、质量标记与几何标准差 | CEOS-ARD 章节 4（4.3/4.4） |
| 定标可追溯 | 定标因子、辅助数据版本、处理器版本 | 版本台账 |

## 5. 输出形态

逐条自评表（而非笼统结论）：

```
| 条款 | 级别 | 状态 | 说明 |
| 4.3 Geometric Accuracy | Threshold | Achieved | ALE 0.55 m，方法见引用 |
| 4.4 Geometric Refined Accuracy | Goal | Not Achieved | 未提供几何标准差 |
| 噪声矢量 | Threshold | Achieved | noise_range 查找表存在 |
```

## 6. 实现建议

1. **规则引擎骨架**借鉴 stac-check（MIT，JSON Schema + lint 结构），条款清单用 CEOS-ARD v1.3.1。
2. **与版本台账联动**：定标常数可追溯规则要求元数据携带处理器版本号、辅助数据版本号。
3. **优先实现 Threshold 级规则**，Goal 级作为进阶。
4. 参考 s1ard（CARD4L 注释层与合规输出模板）作为输出格式对齐基准。
